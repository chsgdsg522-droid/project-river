# Project River 德州扑克游戏设计

日期：2026-09-23  
状态：已由用户确认  
项目类型：响应式网页游戏 / 纯虚拟筹码德州扑克  
首版目标周期：2–4 周

## 1. 产品定义

Project River 是一款面向德州扑克新手和朋友聚会的网页游戏。玩家无需注册即可创建私人房间、通过链接邀请朋友，并由机器人补齐空位完成一局固定十手的快速对局。产品同时提供单人练习和三分钟新手教程。

产品只使用不可兑现的虚拟筹码，不支持充值、提现、现金桌、现实奖品或任何现实利益交换。首页明确说明：“仅使用虚拟筹码，不支持充值、提现或现实奖励。”

项目兼具两个目的：

1. 成为朋友之间可以直接使用的私人牌局工具。
2. 成为可公开展示源码与在线试玩的个人作品。

首版主要服务中国大陆用户，界面以中文为主。所有关键扑克术语同时显示国际通用英文，例如 `弃牌 Fold`、`过牌 Check`、`跟注 Call`、`加注 Raise`、`全下 All-in`。产品临时代号为 Project River，正式命名、域名和商标检查留到原型完成之后。

## 2. 成功标准

首版成功不是页面可以打开，而是下列场景完整成立：

一名玩家打开网页后，无需注册即可创建房间并获得邀请链接。另一名玩家通过链接加入，剩余座位由机器人补齐。两名真人和机器人完成十手牌，期间能够正确处理加注、全下、边池、行动超时、短暂断线、机器人接管和真人恢复。结束后显示正确排名及当局摘要，并可由房主发起下一局。

工程验收还要求：

- 常见牌型、下注流程和边池结算正确。
- 客户端不能获得其他玩家未公开的底牌。
- 桌面端和手机端均可完整游戏。
- Chrome、Safari、Edge、Firefox 当前版本均可使用。
- 深浅主题、双色/四色牌、静音和减少动画设置均有效。
- 约十桌、最多约六十人同时在线时保持稳定。

## 3. MVP 范围

### 3.1 包含

- 创建好友房、通过六位房间码或邀请链接加入。
- 单人练习和可跳过的三分钟新手教程。
- 六人等待房、房主控制、真人和机器人混合入座。
- 完整德州扑克流程：盲注、下注轮、Fold、Check、Call、Bet、Raise、All-in、边池、摊牌与结算。
- 固定十手快速局和最终筹码排名。
- 关键扑克术语双语展示及可查询术语表。
- 快捷加注比例与金额滑杆。
- 预设短语和表情，不支持自由聊天。
- 五个拥有固定头像、名字和打法性格的机器人。
- 克制的发牌、筹码、当前行动者、摊牌和获胜动效与音效。
- 深色和浅色主题；传统双色牌和四色牌切换。
- 桌面、平板和手机响应式界面。
- 结束页排名、最终筹码和当局摘要。
- 昵称、头像、偏好及累计统计保存在本机。
- 匿名错误和性能监控。
- 本地运行说明；公网部署作为后续步骤，不阻塞本地 MVP。

### 3.2 不包含

- 账号、邮箱、手机号或第三方登录。
- 充值、提现、付费筹码和现实奖品。
- 公开房间大厅和自动匹配。
- 自由文字聊天、语音、私信。
- 永久牌局历史和逐手回放。
- 多种牌局模式、现金桌、完整锦标赛系统。
- 全球排行榜、成就和复杂经济系统。
- 长期云端玩家资料和朋友关系。
- 多地区部署或旧版浏览器兼容。

## 4. 游戏规则

### 4.1 基本结构

- 最多六个座位。
- 一至六名真人均可开局。系统默认用机器人补齐六席；房主可以在开始前移除机器人，但整桌至少保留两名参与者。
- 每名玩家初始拥有 1,000 虚拟筹码。
- 每局固定十手牌。
- 第 1–4 手盲注为 10/20。
- 第 5–7 手盲注为 20/40。
- 第 8–10 手盲注为 40/80。
- 玩家筹码输光后本局淘汰，只能旁观。
- 第十手完成后按最终筹码排序；筹码相同则并列。
- 如果第十手之前只剩一名未淘汰玩家，牌局提前结束。

### 4.2 行动与计时

- 每次行动限时 15 秒。
- 超时时，如果可以 Check 则自动 Check；否则自动 Fold。
- 操作顺序固定为 `Fold → Check/Call → Bet/Raise`。
- 下注和加注金额必须由服务端验证。
- 点击 `Raise` 后显示快捷比例、滑杆以及明确的“加注至 Raise to”金额。
- 面对底池 240、对手下注 80 的示例中，界面应说明“加注至 320”表示本轮总下注提高到 320，而不是额外增加 320。

### 4.3 加入、旁观与断线

- 中途加入者先作为旁观者，本局结束后才能入座。
- 旁观者只看到公共信息，不能看到未摊牌底牌。
- 玩家断线后保留座位 30 秒；轮到该玩家时按超时规则处理。
- 超过 30 秒仍未恢复时，由机器人接管座位。
- 真人重新连接后，如果机器人尚未开始下一手则立即恢复；否则在下一手恢复。
- 房主短暂离线时保留权限；长期离开后，权限转交最早加入的在线真人。
- 房间无人在线 30 分钟后销毁。

## 5. 教学与扑克术语

### 5.1 双语原则

普通说明保持中文，只有关键扑克概念使用中英双语。首版至少覆盖：

- 弃牌 Fold
- 过牌 Check
- 跟注 Call
- 下注 Bet
- 加注 Raise
- 全下 All-in
- 底池 Pot
- 翻牌 Flop
- 转牌 Turn
- 河牌 River
- 摊牌 Showdown
- 庄家 Dealer / D
- 小盲 Small Blind / SB
- 大盲 Big Blind / BB

术语可通过点击或悬停查看解释，同时在设置或帮助中提供完整术语表。

### 5.2 三分钟教程

首次进入时主动推荐教程，但允许跳过。教程通过脚本化牌局依次讲解：

1. 底牌和公共牌。
2. 五张最佳组合与基础牌型。
3. SB、BB、Dealer 与行动顺序。
4. Check、Call、Bet、Raise、Fold、All-in。
5. Flop、Turn、River 和 Showdown。
6. 底池、下注金额和“加注至”的含义。

### 5.3 单人练习与好友局公平

单人练习可以开启实时胜率、底池赔率和策略说明。好友局只显示规则信息，包括当前牌型、合法操作、跟注金额和术语解释，不显示胜率或推荐动作。

## 6. 页面与流程

### 6.1 首页

首页提供四个主要入口：

- 创建好友房
- 加入房间
- 单人练习
- 新手教程

首次使用时选择昵称和扁平插画头像。以后从浏览器本地恢复。首页展示纯虚拟筹码声明。

### 6.2 创建房间

首版不提供复杂规则设置。创建后直接生成六位房间码和邀请链接，并采用本设计规定的十手规则。

### 6.3 等待房

等待房显示六个座位，以及真人、机器人和空位状态。房主可以：

- 移除玩家。
- 添加或移除机器人。
- 复制邀请链接或房间码。
- 开始牌局。

至少一个真人和一个对手即可开始。默认状态下空位由机器人补齐至六席；房主可以减少机器人数量，最低保留两名参与者。

### 6.4 好友牌桌

牌桌显示底池、公共牌、各玩家公开筹码、当前行动者、下注状态、当前手数、盲注级别和倒计时。每名玩家只看到自己的底牌。术语可查看解释，Raise 打开快捷比例和滑杆。

### 6.5 单人练习

单人练习复用同一套规则和机器人，但无需等待其他用户。教学辅助可独立开关。

### 6.6 结束页

结束页展示：

- 最终排名和筹码。
- 每名玩家赢得的手数。
- 本局最大底池。
- 最大筹码上升或逆转等摘要。
- 房主可用的“再来一局”操作。

系统不提供逐手回放。摘要只在当局内计算，离开结束页后丢弃原始行动记录。

## 7. 视觉与交互

### 7.1 视觉原则

产品定位为“现代桌游工具”，不是赌场模拟器：

- 深色为默认主题，完整支持浅色主题。
- 不使用绿色绒布、木纹、霓虹灯、金币雨或老虎机式反馈。
- 不绘制厚重实体牌桌，只使用轻微椭圆轮廓组织座位。
- 手牌和公共牌拥有最高对比；底池、筹码和倒计时为第二层级。
- 桌面端保留完整六人信息；手机端压缩其他玩家信息并强化自己的手牌和操作区。

### 7.2 动效和声音

- 动效仅表达发牌、筹码移动、行动者切换、摊牌和获胜。
- 普通状态转换约 150–250ms，发牌和摊牌可以稍慢。
- 支持系统“减少动态效果”。
- 默认开启克制的发牌、筹码、轮到你和胜利音效。
- 提供一键静音，不播放背景音乐。

### 7.3 无障碍

- 花色同时使用颜色和符号，不只依赖颜色。
- 当前玩家同时通过轮廓、文字和倒计时标识。
- 手机点击区域至少约 44px。
- 桌面端支持键盘完成 Fold、Check/Call、Raise 和金额确认。
- 四色牌、浅色主题、静音和减少动画可分别设置。

## 8. 机器人设计

所有机器人使用与真人相同的合法动作接口，不能读取真人底牌或任何隐藏信息。角色描述只提供模糊线索，不暴露准确策略参数。

- 松果：喜欢入池，很少轻易弃牌，方便新手看到更多摊牌。
- 岩叔：谨慎紧手，下注时通常拥有较强牌力。
- 小满：主动激进，偶尔连续施压或诈唬。
- 阿策：重视位置和底池赔率，打法最均衡。
- 悠悠：变化较多，偶尔慢打强牌，但不会随机行动。

机器人目标是表现得像合理的休闲玩家，而不是接近专业求解器。批量模拟应能观察到五个角色在入池率、加注率和弃牌率上的差异。

## 9. 技术架构

### 9.1 开源基础

以 [Elite Poker](https://github.com/opadips/Elite-Poker) 的 MIT 代码为起点，保留其许可证和原作者版权说明，并在仓库中注明改造来源。实现前先检查现有代码边界，再进行针对性拆分，不进行无必要的全面重写。

视觉原则参考 [Pip](https://github.com/playpip/pip-web) 对“非赌场化”扑克体验的处理，但不复制 Pip 的品牌、插画或界面资产。

### 9.2 模块

**网页端：React + Vite**

- 实现首页、等待房、牌桌、教程和结束页。
- 使用一套响应式组件服务电脑与手机。
- 通过设计变量实现主题与牌面模式。
- 使用浏览器本地存储保存玩家资料、偏好和累计统计。

**实时服务端：Node.js + WebSocket**

- 管理房间、座位、旁观、房主、重连和销毁。
- 管理十手牌流程和 15 秒行动计时。
- 执行机器人操作。
- 向每个客户端广播经过过滤的专属状态。

**纯游戏引擎**

- 负责洗牌、发牌、盲注、行动顺序、合法操作、下注轮、全下、边池、牌型判断和结算。
- 不依赖界面和网络，能够独立测试。
- 好友局与单人练习使用同一套规则。

### 9.3 数据流

`玩家操作 → 服务端验证 → 游戏引擎生成事件 → 更新房间状态 → 为每位用户生成安全视图 → WebSocket 广播`

客户端只提交意图，不能自行修改筹码、发牌或推进回合。

### 9.4 存储和监控

首版不使用数据库：

- 房间和对局状态保存在服务器内存中。
- 房间无人在线 30 分钟后删除。
- 昵称、头像、设置和累计统计保存在玩家浏览器。
- 监控只采集匿名访问量、错误和性能信息。
- 日志不得包含底牌、昵称、聊天内容或完整牌局记录。

### 9.5 公平与安全

- 服务端使用安全随机数洗牌。
- 每个操作携带牌局编号和动作序号，重复提交不得重复执行。
- 断线重连使用临时玩家令牌恢复座位。
- 昵称限制长度和字符，并在显示前转义。
- 其他玩家的底牌不发送到无权查看的客户端。
- 所有下注、计时、胜负和筹码变化由服务端裁决。

## 10. 异常处理

- 网络中断时停止提交操作，显示“正在重连”，客户端不得自行推进游戏。
- 非法或过期操作由服务端拒绝，并返回最新安全状态。
- 重复点击通过动作序号去重。
- 行动超时按 Check 优先、否则 Fold 处理。
- 房主永久离开时自动转移权限。
- 服务器重启会丢失房间；首版需在界面中明确说明，并提供返回首页的恢复路径。
- 单人模式若发生异常，允许重新开始当前局，不写入错误统计结果。

## 11. 测试策略

### 11.1 游戏引擎单元测试

- 所有牌型和同牌型比较。
- 平局与分池。
- Fold、Check、Call、Bet、Raise、All-in 合法性。
- 最小加注、短码全下和多层边池。
- 无人跟注时的提前获胜。
- 庄家、SB、BB 和行动顺序轮换。
- 十手牌和三个盲注阶段。

### 11.2 机器人模拟

- 批量运行至少数千局，不得卡死、出现负筹码或非法行动。
- 检查五种角色在统计上具有可观察差异。
- 检查机器人只使用其可见信息。

### 11.3 实时集成测试

- 创建、加入、旁观、开始和再来一局。
- 六名真人及混合机器人组合。
- 重复操作、网络延迟、刷新和断线。
- 30 秒接管和真人下一手恢复。
- 房主转移、行动超时和空房销毁。
- 不同身份收到正确的安全视图。

### 11.4 浏览器与界面测试

- Chrome、Safari、Edge、Firefox 当前版本。
- 常见电脑、平板和手机尺寸。
- 深色/浅色、双色/四色、静音和减少动画。
- 键盘、触摸、长昵称和双语术语布局。
- 15 秒倒计时和当前行动者清晰可见。

## 13. 部署边界

首版首先保证本地完整运行。公网部署目标仍保留，但预算尚未确定，因此具体服务商和部署拓扑不在本设计中锁定。选择平台时必须满足：

- 支持持久 WebSocket 连接。
- 服务器不会因短暂空闲频繁休眠，或能够接受对应体验损失。
- 能运行单实例 Node.js 服务。
- 可以配置匿名错误与性能监控。
- 对中国大陆首批玩家具有可接受的连接质量。

在用户确定预算后，再比较具体平台和费用。

## 14. 已确认决策摘要

- 纯虚拟筹码，无充值、提现或现实奖励。
- 中国大陆新手和朋友为首批用户。
- 网页端，电脑与手机均要求高完成度。
- 6 人桌、10 手牌、真人和机器人混合。
- 无账号，邀请链接或房间码加入。
- 中文主界面，关键术语中英双语。
- 15 秒行动，超时 Check 优先，否则 Fold。
- 好友局不显示胜率和策略建议。
- 不保存永久牌局历史，只保存本地累计统计。
- 公开 GitHub 仓库，保留 MIT 归属。
- 首版约支持十桌、六十人同时在线。
- 本地 MVP 优先，公网部署预算之后决定。
